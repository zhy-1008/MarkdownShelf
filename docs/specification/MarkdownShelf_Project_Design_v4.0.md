## 1. 产品目标与决策基线

MarkdownShelf 是面向技术笔记的离线文档库。用户可以集中导入已有 Markdown 和 TXT，按分类和标签组织笔记，通过书架和全文搜索定位内容，在应用内以接近 Typora 的即时渲染体验编辑，并将文档导出成普通 Markdown。文档库能跨电脑迁移，支持版本回退、回收站和整库恢复。第一版提供简体中文界面，架构预留国际化和 C++ 核心的跨平台能力。

## 2. 技术架构与仓库

~~~text
PySide6 / Qt Widgets ── Controllers ── JobDispatcher
    │ Qt 主线程                       │ 后台执行与结果信号
    └─ QWebEngineView / QWebChannel   └─ pybind11 / _markdownshelf_core.pyd
         └─ 本地 Vditor IR + 源码视图      └─ C++17 services
                                          ├─ SQLite + FTS5
                                          ├─ Markdown 解析与导入导出
                                          ├─ 图片、版本、快照与恢复
                                          └─ 平台抽象与文件系统
~~~

| 层 | 所有权与边界 |
| --- | --- |
| C++ 核心 | 文档、分类、标签、搜索、导入导出计划、索引、版本、图片引用、备份、迁移和数据校验。拥有 SQLite 与库文件写权限，业务规则可在无 Qt 环境下测试。 |
| pybind11 | 暴露值类型和有限服务方法，转换 UTF-8、结构化结果与异常。对纯 C++ 阻塞工作释放 GIL，Python 回调仅在显式获取 GIL 后执行。SQLite 连接和语句句柄留在 C++。 |
| Python 应用 | 库启动调度、进程/窗口生命周期、Qt 任务调度、设置与脚手架、界面模型、命令路由、错误呈现。修改业务数据一律走 C++ 服务。 |
| 编辑器 Web 层 | IR 页面、源码编辑控件、光标与选择、渲染和键盘事件。本地静态资源、限定来源和消息接口。Python 负责保存调度。 |
| 平台层 | Windows 路径、共享和重命名语义、跨进程互斥及 IPC。业务层用标准 C++17、RAII、`std::filesystem` 与明确的资源所有权。 |

### 2.2 开发运行契约

CMake 提供 `win-x64-debug`、`win-x64-release` 配置、构建和测试 presets。在 VS Code 的 x64 Developer PowerShell 中确认 MSVC、CMake 及 CPython 的版本和位数，再使用同一个虚拟环境配置和安装扩展。模块安装到暂存根目录，Python 源码从 `src/python` 加载。仓库创建后由 README 维护下列命令。首条 `python` 命令须指向已核对的 64 位 CPython 3.12，必要时使用解释器完整路径。P1.1 验证到绑定加载及其 pytest 测试，应用启动和 GUI 命令在 P1.5 具备最小 PySide6 入口后验证。

~~~powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --require-hashes -r requirements-dev.lock
cmake --preset win-x64-debug -DPython_EXECUTABLE="$((Get-Command python).Source)"
cmake --build --preset win-x64-debug
ctest --preset win-x64-debug --output-on-failure
cmake --install build/win-x64-debug --config Debug --prefix .stage/debug
$env:PYTHONPATH = "$PWD\.stage\debug;$PWD\src\python"
python -c "import _markdownshelf_core"
python -m pytest tests/python
# P1.5 起验证应用入口和 GUI smoke test
python -m markdownshelf
python -m pytest tests/gui
~~~

为避免普通 Windows CPython 与调试运行库冲突，阶段一以实测可导入为门槛。若 Debug 配置要求调试版 Python，则把默认开发绑定配置改为 RelWithDebInfo，并保留 C++ 独立 Debug 测试；将最终可运行命令、IDE 调试配置和 ABI 检查记录在阶段文档。

### 2.3 C++ 工程规范与跨语言契约（工程规范）

- P1.1 提交根目录 `.clang-format`，固定工具版本。项目 C++ 代码在 CI 执行 `clang-format --dry-run --Werror`，第三方代码排除在格式检查之外。推荐格式基于 LLVM，围绕现有项目代码统一配置。
- 命名采用类型 `PascalCase`、函数和变量 `snake_case`、成员尾缀 `_`，命名空间 `markdownshelf`。公共契约位于 `include/markdownshelf/`，模块内实现与私有头按职责就近放置。使用独立 CMake target 约束依赖，持续验证核心可在无 Python、Qt、PySide6 的环境构建。SQLite 与业务文件只能由 C++ 服务访问。
- SQLite 连接/语句/事务、文件句柄、锁、后台任务票据、临时目录均以 RAII 管理。独占所有权默认用值对象或 `std::unique_ptr`；只在真实共享生命周期时用 `std::shared_ptr` 并说明退出协议。借用参数标明寿命，析构释放路径不抛出。服务失败须保留数据不变量，数据库与发布路径按事务和回滚日志恢复。
- MSVC 一方代码启用 `/W4`，CI 对新增或修改的一方目标执行警告即错误。静态分析首选 MSVC `/analyze`；如锁定工具链已验证 Clang-Tidy，也可通过 CMake 接入等效检查。记录确需抑制的单个告警、理由和范围。审查检查线程和 GIL、边界输入、事务原子性、资源归属、版本兼容及错误可诊断性。
- `tests/contracts/` 保存版本化 DTO 样例和错误码，C++ 单测验证服务字段/语义，Python 集成测试通过真实 `.pyd` 核对 UTF-8、UUID、可空字段、整数范围、事务错误和取消状态。JS 单测覆盖 WebChannel 协议版本、序号、可空参数、超限和迟到消息，PySide6 + 实际 WebEngine 集成测试串起「编辑 → Python → C++ 写入 → ACK」。检查 UTF-8 字节区间到 Qt/JS UTF-16 的转换，样例含中文和代理对。失败输出使用稳定错误码和本地化消息键。契约变更须更新样例、两端测试和学习文档。

### 2.4 离线、隐私及语言管理

**用户已确认**：V1.0 完全离线，无账号、登录或云同步。应用不上传文档、图片、搜索记录或关键词、遥测、使用数据和崩溃采样。编辑器、代码高亮、词典、图标、字体及其他实际使用的第三方运行资源均本地打包，Qt WebEngine 不访问在线 CDN、外部字体或远程图片。用户主动打开 HTTP/HTTPS 外链时由系统浏览器接手。

**实施契约**：Qt 文案统一用 `tr()/QTranslator` 及 `zh_CN` 资源，Web 侧用同一语言注册表的 locale 和本地中文资源，包括 Vditor 内置工具栏、菜单和提示的中文覆盖。`src/python/markdownshelf/i18n/` 发布语言配置，以版本化的本地 JSON 给编辑器页面传递资源和语言 ID。服务只返回消息键、参数和错误码。用户可见的错误、状态、任务、帮助和默认对话框均用简体中文。保留扩展 locale 的资源入口，V1.0 固定使用简体中文。

验收在无外网的干净 Windows 测试机上做完整功能，并在网络可用的隔离测试环境记录应用及 WebEngine 的请求，确认没有对外发送。日志核对敏感字段；检查 Qt 和 Vditor 的空态、错误、菜单、工具栏、编辑状态的中文覆盖与初始化顺序。用户编辑的 Markdown 和语言代码原样保留。见 T12、T13、T16、T18。

## 3. 文档库、线程与数据契约

### 3.1 目录、创建与打开

~~~text
WorkLibrary/
  library.db
  library.json
  assets/
    <uuid>.<extension>
~~~

- `library.json` 使用 UTF-8 JSON，包含 `format`（固定魔数 `MarkdownShelfLibrary`）、`format_version`、`library_uuid`、`created_utc`。数据库有相同 UUID 及 SQLite `application_id`；数据库 `user_version` 表示 schema 版本。文档库显示名称在 DB 持久化。将三项分别用于识别格式、确认库身份、检查数据库迁移前置条件。
- 欢迎页提供「创建新文档库」和「打开已有文档库」。新建填写名称并选择父目录，检查 Windows 合法名称和可写性，建立同名库。目标非空时明确报错。先在同卷暂存初始化，再发布到不存在或经再次确认为空的目标，失败只清理本次生成的文件。打开时核验根目录、清单、DB 身份、schema、资源目录和锁；只有成功后更新登记。
- 在关闭源库实例后复制完整文件夹到新电脑，目标电脑选择该文件夹打开。迁移向导也可接收经验证的完整备份。库移动后按 UUID 重新定位已登记条目。遇到同 UUID 的另一物理副本时提示身份冲突并保持登记明确。两台电脑间复制的副本由用户选择主库，V1.0 不提供合并。
- 开库时轻量检查元信息与 SQLite 快速检查的策略由阶段一测量确定；完整检查用于备份恢复、迁移和诊断。遇到较新 schema、损坏或权限问题，以明确错误终止写入并保留原文件。资源单项缺失可在已通过结构校验的库中显示占位及诊断，完整备份验证仍须报告缺失。
- Windows 路径先规范化并验证最终句柄指向；支持普通中文、空格及符合目标系统的长路径。库首版以本地、可写、支持所需锁与重命名的文件系统为基线，同步盘和网络共享的可用性须通过同样的能力检测。校验目录联接、符号链接及别名的物理身份。

### 3.2 同库独占及跨实例协调

每个用户会话通过 UUID 对应的 Windows 命名互斥对象串行化开库、恢复、迁移和分发备份任务。再对库父目录中稳定的锁文件取得系统句柄独占锁，挡住同一路径的并行写入，且原位替换期间不释放。用规范化路径、物理身份和 UUID 校验防止同路径别名或同库复制件误开。互斥由专用会话协调线程获取并在同一线程显式释放，进程终止时由系统处理遗弃状态。文件锁随句柄关闭释放，陈旧 PID/路径记录只作诊断。

独占所有者暴露受本机同用户权限约束的 IPC。仅接受有限命令 `activate`、`request_backup`，验证版本、UUID、请求 ID 和格式。重启重复开库时激活已有实例并返回；若启动竞争而 IPC 尚未就绪，有限等待后提示占用。不同 UUID 通过各自进程和窗口打开。互斥、锁和 IPC 放在可替换的平台接口，应用以两个进程进行测试。

全局配置和库登记用短时全局锁进行读改写、同目录临时文件与原子替换；按字段或条目合并更新。独占库所有者负责该库的备份，后台调度按库 ID 与日期去重；空闲库由取得同样独占锁的任务负责。恢复或迁移期间同一库的备份延后。备份路径变更与运行中任务串行提交，任务记录自己的目的路径。

### 3.3 SQLite 模型

整数主键用于联接与 FTS rowid，公开实体以稳定 UUID 寻址。时间统一存 UTC epoch 毫秒，UI 转本地时间。正文用 UTF-8 `TEXT`，输入规范化为 LF；游标位置和匹配片段显式标识字符偏移单位，JS 边界转换为 UTF-16 索引。所有名称、哈希和报表的排序规则需可复现。

| 表 | 最小字段及约束 |
| --- | --- |
| `library_meta` | 单行，`library_uuid`、`display_name`、`created_at`、`search_index_version`、`active_fts_slot`、`content_epoch`。应用标识及 schema 版本使用 PRAGMA。 |
| `categories` | `id`、`uuid UNIQUE`、`parent_id NULL FK`、`name`、`name_key`、`position`。同一父节点下 `name_key` 唯一，根节点用单独唯一索引。空分类用文档的空 FK 表示。更新时验证父节点存在且无环。 |
| `documents` | `id`、`uuid UNIQUE`、`category_id NULL FK`、`title`、`title_sort_key`、`body_md`、`body_sha256`、`import_fingerprint NULL`、`revision`、`favorite`、`created_at`、`modified_at`、`last_read_at NULL`、`deleted_at NULL`。索引至少覆盖正文/导入指纹、分类与活跃态、各排序字段及回收站过期条件。 |
| `tags` / `document_tags` | 标签含 `id`、`uuid UNIQUE`、`name`、`name_key UNIQUE`。名称去首尾空白，用固定 Unicode 规则计算 `name_key`（NFC + 无区域大小写折叠后转 NFC），保留用户输入的显示大小写。联接表以 `(document_id, tag_id)` 为复合主键，两列是 FK，另建 `(tag_id, document_id)` 反向索引。两端删除级联清理联接。 |
| `assets` | UUID、内容 SHA-256 唯一、受控相对路径、MIME、长度、创建时间。`document_assets`、`version_assets`、`draft_assets` 以持有者 ID + asset ID 为主键。持有者删除级联。提交关系与正文同事务。未提交的文件由作业保留引用保护，GC 同时检查三表及第 5.4 节的临时和快照保留引用。 |
| `document_versions` | `id`、文档 FK、来源 revision、标题快照、正文、摘要、原因、创建时间、`pinned`；按文档+时间索引。 |
| `drafts` | 每文档一个草稿，含 `base_revision`、`edit_session_id`、`edit_seq`、`body_md`、`updated_at`，以及 UI 恢复所需的模式和游标。 |
| `library_settings` / `workspace_state` | 库配置和会话状态独立存放，含结构版本。`library_settings` 保存视图偏好、`default_shelf_sort`、`category_sort_by_uuid`、保留期限等。`workspace_state` 保存打开标签与浏览位置。`schema_version` 与配置版本分别管理。分类排序的键值、默认值和清理规则见第 4.2 节。 |
| `search_fts`（逻辑名称） | FTS5 `title, body, category_path, tag_names` 四列，`rowid = documents.id`，每篇活跃文档一行。数据是可重建的搜索投影。重建使用固定名称 `search_fts_a` 和 `search_fts_b`，`library_meta` 的 `active_fts_slot` 指向当前表。投影内容及 epoch 维护见第 6 节。 |
| `search_rebuild_changes`（索引重建期间） | `rebuild_id`、`document_id`、`change_epoch`，以 `(rebuild_id, document_id)` 为主键，不级联删除，确保删除的文档也可以追补。 |
| `asset_gc` / `backup_runs` | 待清理资产含 UUID、路径、哈希及可重试状态，已移出资产目录表的清理记录仍可追踪。备份记录含已完成的备份日期、UTC 时间、错误摘要。经校验并正式发布的 ZIP 清单可用于识别已完成任务。 |

为连接启用 `foreign_keys=ON`、有界 `busy_timeout`。可写本地库使用 WAL，首版以 `synchronous=FULL` 为持久性基线。每库一个串行写入队列，后台搜索使用线程专属只读连接。UI 只接收 DTO 和信号。读任务结束后释放事务，避免 WAL 持续膨胀。锁顺序固定为库独占、短时维护屏障、SQLite 事务。跨库任务不得持有一个库的事务等待另一个库的锁。

文档、分类、标签及关联变更均走每库写队列与明确事务。按操作在同一事务完成 revision 校验、版本快照、图片引用及第 6.2 节的 FTS 投影变更。影响查询结果、回传元数据或排序时，在同一事务递增 `content_epoch`，提交后发布结果失效通知。重复提交同一 `command_id` 在当前任务生命周期内共享结果；可恢复的跨重启作业以事务记录、内容版本或备份发布日志验证是否已经应用。

`SaveResult` 返回 UUID、已提交 revision、已确认的编辑序号、保存时间及是否创建版本。`TagSummary` 返回 UUID、显示名和活跃文档数。`TagMutationResult` 返回影响文档数（活跃、回收站分别统计）、实际增删关联数、保留/移除标签 UUID 及提交后的结果版本。`SearchQuery` 包含 `text`、分类范围（全部、指定分类及后代、未分类）、标签 UUID 集合、排序、页大小和游标。`DocumentSummary` 提供文档 UUID、标题、分类、标签、最后修改时间和纯文本正文摘要，图标与封面由 UI 生成。`SearchHit` 提供文档 UUID、标题、分类路径、标签、最后修改时间、正文摘要、可空的 `relevance_score`，以及按字段分组且标明偏移单位的匹配区间。正文匹配区间附原文来源 `body_text`、`inline_code` 或 `code_block`，第 6.1 节定义显示方式。`Page` 含游标和 `content_epoch`。`TransferReport` 含逐项结果、汇总、可定位的问题和回滚状态，导入额外返回 `link_summary` 和 `link_issues`（第 7.2 节）。核心错误枚举至少包括 `InvalidInput`、`LibraryBusy`、`NotFound`、`RevisionConflict`、`UnsupportedFormat`、`SchemaTooNew`、`IntegrityFailed`、`IoError`、`Cancelled`。跨语言传递 `code`、本地化消息键、可重试性及操作 ID。普通批量动作同一事务成功或回滚，输入无效时返回未更改的清单；单篇和批量的标签增删统一调用 `Document.change_tags`。导入按依赖连通组提交，见第 7 节。`cancel_token` 由任务调度器拥有，可并发发出取消。`progress_sink` 发布有类型的阶段、计数和状态，经有界事件队列送至 Qt 主线程。具体中止行为见第 9.3 节。

`SortSpec` 为字段 `modified_at / last_read_at / created_at / title` 加方向 `asc / desc`。`ListQuery` 传入当前范围、去重后的标签 UUID 集合、已解析的 `SortSpec` 和页游标。`get_shelf_sort` 传入实际分类 UUID 时返回该分类的有效排序，省略 UUID 时返回文档库默认排序。设置写入校验分类仍存在与枚举合法，成功后返回持久化值，详见第 4.2 节。

历史比较的两端复用 `Version.preview(uuid, version_id)` 读取同篇文档的两份不可变正文，时间和 ID 在界面上区分。参见第 5.3 节。

`ProtectedCopyInfo` 包含不透明的 `copy_id`、库 UUID、目录显示路径、恢复操作时间和状态。删除依据库 UUID 与副本 ID 解析受管目录，界面显示的路径不作为删除参数。`DeleteProtectedCopyResult` 回报已删除、未开始或待重试及原因。验证、锁与失败收尾见第 8.2 节。

`AssetRef` 返回受控的资产 UUID、URI 及按所有者隔离的作业保留引用（`lease_id`）。编辑会话保存正文或草稿时传入所用 `asset_leases`，导入的资产引用由 `Import.commit` 在服务内管理。关页放弃、取消或完成后通过 `Asset.release_job` 释放作业持有的保留引用。备份保留引用由 `Backup.take` 持有，调用方不直接管理。第 5.4 节及第 8.1 节定义生命周期。

`ImportPlan` 保留 `plan_id` 和每行的 `candidate_id`、稳定 `source_key`、`source_path`、`default_title` 与可选 `title_override`。`ImportOptions.title_overrides_by_source_key` 用于重新预览同一来源时带入已有编辑。提交时，`ImportResolution` 以 `candidate_id` 传入最终的动作、所需的目标 UUID/revision 和可选的 `title_override`。显式空字符串按无效标题处理，缺省 override 表示按第 7.1 节默认规则计算。提交使用当前计划和最终决策，预览期间不写入文档。

## 4. 桌面交互与配置

### 4.1 书架与导航

主窗口顶部提供文档库入口、全局搜索入口和工作区操作。左栏含分类树、标签、全部文档、未分类、收藏、最近阅读、回收站。中间在首页和文档标签间切换。右栏编辑时显示大纲，书架可显示选中文档信息。左右栏分别记录显示状态与宽度。无文档时提供新建和导入入口。窗口采用第 12 节的设计系统，支持浅色、深色手动切换。Qt 与 Web 编辑器均使用统一主题，文案遵循第 2.4 节。

- 书架首次默认网格卡片视图，网格和列表共用同一结果模型。只有自动封面，按标题首字符、稳定配色和分类图标生成，未分类有默认图式，改分类后刷新。卡片显示封面、标题、正文摘要、标签、分类及最近修改时间。列表显示文档图标、标题、分类、标签和最近修改时间。正文摘要由核心按页提供，从正文生成纯文本摘录，空正文可显示空态。库默认最近修改降序，支持最近阅读、创建时间、标题及升降序。实际分类按 UUID 独立保存排序偏好，首次访问继承库默认。网格、列表共用该偏好。排序的最后比较键用 ID 保持翻页稳定，作用域和回退见第 4.2 节。
- 分类为多级逻辑树。支持创建、改名、子分类、拖放层级与同级排序。父分类显示后代文档。移动拒绝自引用和循环。删除只移除选中的分类节点，将直接归属的文档移入未分类（`category_id = NULL`）。直接子分类提升到被删除分类的原父级。若删除的是顶级分类，直接子分类提升为顶级分类。子分类及其后代中的文档继续归属原分类。删除前预览受影响数量，并按删除后的同级节点检查名称冲突。发生同级重名则回滚并显示冲突名称，用户可先改名再删除。

  **数据安全不变量。** 分类删除不删除任何文档。已有文档的 UUID 与 Markdown 正文保持不变，原本有效的 UUID 内部链接继续指向同一文档。分类节点、文档归属、子分类提升、排序配置清理和索引维护属于同一写事务。分类关系调整或相关写入失败时整个事务回滚，原有数据、配置和索引全部保持原样。索引维护见第 6.2 节。
- 左栏、卡片及文档详情/属性中的标签可点击。卡片与属性共享基于标签 UUID 的导航命令，进入关联文档列表，可返回点击前的书架浏览位置。组合标签默认 AND，仍可与分类、收藏及关键词共同使用。交互与失效处理见第 4.4 节。
- Ctrl 多选、Shift 连选、书架焦点下 Ctrl+A 作用于当前筛选，Esc 清除书架选择及 Shift 连选锚点。文本输入、对话框或查找面板拥有焦点时由对应控件处理 Esc。全选动作捕获结果 ID 或查询与版本，执行前验证范围未漂移。支持批量移分类、增删标签、收藏/取消收藏、导出和移入回收站。操作结果展示完成数量与失败原因，删除类动作先确认。
- 文档可重名。新建要求非空标题，可选分类和标签，进入编辑器。元数据标题可改，正文 H1–H6 单独编辑，靠 UUID 保持链接和选中状态。最近阅读以打开/聚焦实际文档时更新，避免把仅浏览结果算入阅读。
- 收藏、分类与首页等守卫排除回收站文档。回收站可恢复、永久删除选中项、清空。恢复保留标签、收藏和还存在的分类，分类已被删除则归未分类。永久删除联动清理草稿、版本及最终无引用图片。删除前所有受影响标签页须完成保存或由用户处理未保存编辑。启动和定时批量清理默认超过 90 天的项并记日志。

**分类排序的工程实现。** 复用 SQLite 的 `library_settings`，以 `category_sort_by_uuid[category_uuid] = {field, direction}` 保存用户设置。还没有配置的分类读取 `default_shelf_sort`，库默认排序未设置时采用最近修改降序。分类命名、父路径、侧栏展开和网格/列表切换均不参与键计算。旧配置缺少映射时视为空映射。

| 书架或查询范围 | 有效排序的读取优先级 |
| --- | --- |
| 实际分类（含后代） | 该分类 UUID 的偏好 → 库默认 → 最近修改降序。分类内叠加标签或切换视图仍用该分类排序。 |
| 全部文档、未分类、收藏及独立标签结果 | 库默认 → 最近修改降序。当前视图显式改排序仅作用于该视图状态，不写任何实际分类。 |

Qt 控制器以窗口、库会话、当前范围和请求序号关联排序读取及分页。只有用户主动在实际分类中改排序才请求 `set_category_sort`，调用使用触发操作时的分类 UUID。C++ 在该库的写队列中按 UUID 读改写映射，提交后通知界面并递增 `content_epoch`。改名和移动保留原 UUID。删除分类时随删除事务清除被删除 UUID 的配置，提升后的子分类各自保留配置，失败回滚配置与分类变更。库默认修改只影响继承默认的分类。切换作用域回填控件时阻断写回信号，忽略旧范围的查询结果。排序变化从新游标加载，失败恢复已保存值并提示。测试覆盖两分类切换、重启、跨库隔离、改名、移动、删除与失败回滚（T02）。

安装版全局配置拟放在 `%APPDATA%/MarkdownShelf/`，库登记为 `libraries.json`，全局设置为 `config.json`。日志拟放在 `%LOCALAPPDATA%/MarkdownShelf/logs/`。便携配置见第 11 节。设置文件含版本，坏配置隔离后回到可用默认，权限问题显示警告，不覆盖原始损坏副本。

日志级别 DEBUG、INFO、WARNING、ERROR、CRITICAL，默认 INFO，单个文件 10 MB，保留 5 个轮转文件。实现可按实例分开写，使用进程安全的统一轮转或单写者控制总量。统一事件格式 `ts_utc / level / layer / instance_id / op_id / event / code / elapsed_ms`。C++ 返回日志事件，Python 汇总，JS 只提交白名单诊断代码和时长。正文、图片数据、搜索原词及可能带原词的异常栈禁止写入日志。模块代码走统一 logger 接口。

### 4.4 标签管理

**用户已确认**：标签为扁平结构，可创建、重命名、删除及合并。单篇或批量文档可加、减标签。点击标签查看关联文档，多标签默认 AND，大小写不敏感去重并保留显示大小写。

**界面设计**：左栏标签区提供「管理标签」入口，打开独立管理页或对话框，逐行显示标签名与关联的活跃文档数量。点击名称或数量进入以该标签 UUID 筛选的书架。行操作为重命名、删除和合并，顶部提供创建。合并需要选择一个不同的现存目标标签，预览来源标签、目标标签、影响的活跃与回收站文档数，并说明目标显示名与 UUID 保留。删除预览影响数量，删除标签后文档仍可编辑和恢复。

- 单篇通过文档属性中的标签选择器加入或移除标签。书架多选后使用同一个选择器的批量模式，展示共同标签、部分关联标签和新增/删除预览。提交只改变用户明确添加或移除的关系；原有其他标签继续保留。使用文档 UUID 与标签 UUID 发起请求。
- 创建、重命名、删除、合并及每次单篇/批量修改各使用一个 C++ 写事务。验证 UUID、名称键、去重后的集合、互斥的增删项和目标仍处于预期状态；对无效文档或标签整批回滚。手动文档标签编辑作用于活跃文档。标签定义的删除、合并应覆盖回收站中仍存在的关联。
- 改名按第 3.3 节的 `name_key` 唯一约束执行。仅更改显示大小写时更新本行显示名。同键指向其他标签时报冲突。合并将来源关联并入目标，以复合主键去重，已带两标签的文档保留一条目标关系，再删除来源标签。普通删除级联清理关系，保留文档、正文、分类、资产和 UUID。
- 服务在同一事务填充受影响文档集、更新 FTS 投影及 `content_epoch`（第 6.2 节）。空标签创建、仅名称大小写变更及标签删除/合并也失效标签管理列表。返回成功后更新计数、选择器与导航，筛选状态按下文同步。失败保持先前的计数、筛选与显示。
- **卡片和属性页导航。** 只读标签 Chip 是独立可聚焦控件，激活时仅发出 `tag_activated(tag_uuid)`。卡片或列表委托识别标签命中区并消费对应的点击、双击及键盘激活，由父卡片处理其余区域。属性页的导航标签与标签选择器的增删控件使用不同信号。点击标签不会触发卡片的文档打开或选中动作，也不会提交属性编辑。Qt 事件隔离参考 [Qt for Python 的事件过滤](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QObject.html#PySide6.QtCore.QObject.eventFilter)。
- **筛选和返回。** 控制器复用现有书架的标签查询。首次从卡片或属性进入标签结果时在当前库的活跃文档中筛选该 UUID。已在标签结果时，新点的 UUID 加入去重集合，全部条件按 AND 匹配。保存点击前的书架状态，包含范围及分类 UUID、筛选 UUID 集合、视图及临时排序、锚定文档 UUID 与滚动偏移。属性页打开自编辑器时采用此前的书架状态，保留编辑标签与未保存缓冲。「返回书架」恢复最近的来源状态，以实际分类的有效排序重新查询并定位锚点。若锚点已失效，选择仍存在的邻近位置或首屏。返回不依赖过期的分页游标或行号。
- **变化同步。** 标签合并的 `TagMutationResult` 将当前与返回状态中的来源 UUID 替换为目标 UUID 并去重。标签删除清除两处失效 UUID 并明确提示，若当前标签结果已无有效标签，则恢复先前的书架范围或回到书架首页。改名只刷新显示。待返回状态也按提交结果清理，丢弃旧 epoch 的异步结果。避免静默以失效标签查询。
- 第 9 节 T15 要求 C++ 事务单测、Python 绑定集成及 Qt 交互验证。多选标签后批量删除或批量合并属于未来扩展示例，V1.0 功能以独立标签的管理和批量文档关联为准。

### 5.1 Vditor 与编辑会话

- 用 `QWebEngineView` 承载内置页面和局部编辑组件。IR 使用 Vditor `ir`。源码模式显示同一 Markdown 的纯文本；阶段一验证锁定版能否把 `sv` 限制为纯源码视图，必要时在编辑器适配器内配置独立的本地源码控件。用户模式保持 IR/源码两项。停用 Vditor 自身缓存，由应用统一持久化。
- 每个标签页以文档 UUID 唯一。重复打开激活原页。默认按需创建编辑器，非活动页面可释放 Web 资源，但须先获得已确认的最新缓冲区并保留 mode、selection、cursor、scroll、editorGeneration。切换模式前完成当前 IME 组合并确认最新的 Markdown 缓冲区和编辑序号，将同一文本原样载入目标视图。无新编辑时沿用已确认的原文，忽略初始化或模式切换产生的渲染回调。若最新缓冲不能可靠取得，则保留当前模式及原缓冲并提示重试。正文、未保存修改及 dirty 状态保持原样，查找位置按第 6.3 节重新计算。初始化、程序化加载、主题切换和焦点同步不应将文档标脏。
- 各页签标题旁显示独立的未保存标记和可访问状态，包括后台标签页。只有最近编辑序号确认提交或用户明确放弃后才清除标记。切换离开有待保存编辑的原页时执行第 5.3 节的切页流程。
- 测试 Markdown 往返，包括中文、代码围栏、表格、缩进、图片 URI、内部链接、未知渲染扩展和多个 H1。正文原样进入源码视图。若 IR 组件对特殊块有有损序列化，在适配器隔离或回退到源码并给出状态提示，禁止因切换模式触发静默内容丢失。
- 格式工具栏分组提供 H1–H6、粗体、斜体、删除线、无序/有序/任务列表、多级块引用、行内代码、带语言代码块、表格插入和调整、外部链接插入与编辑、内部链接、图片、水平分割线、撤销/重做。模式切换和各工具以选区为输入；工具栏与键盘 Undo 路径统一验证。
- 代码块支持本地语法高亮、语言标识、复制、行号切换、水平滚动和编辑，默认未知语言按纯文本显示。核心测试覆盖 C++、C、Python、JavaScript、SQL、Bash、CMake、JSON、XML、YAML。数学或 Mermaid 源码可读可导出，V1.0 不激活其渲染插件。

### 5.2 WebChannel 契约与本地隔离

JS → Python 事件统一携带 `protocol_version`、`doc_uuid`、`editor_generation`、`edit_seq`。方法及事件的有效负载应类型验证，字节和数量限额写入测试。基础事件包括 `ready`、`changed(markdown, position)`、`flush_result(request_id, markdown, position)`、`link_clicked(uri)`、`outline_sync(headings, current_heading_id)` 和 `diagnostic(code)`。可见阅读位置或标题变化时更新大纲，控制器只接受当前文档和编辑器状态的事件。本地图像插入优先用 Qt 捕获选取/拖拽或剪贴板，发给 Web 层的只有合法 URI。Python → JS 包括 `load`、`flush`、`set_theme(theme_payload)`、`find(request)`、`goto_heading`、`insert_markdown`。`find` 与 `find_result` 的参数及过期规则见第 6.3 节。页面初始化时接收第 2.4 节语言配置和第 12 节主题配置，`ready` 后应用当前主题版本。桥接按固定函数与序列化参数调用，页面无法发起任意文件读写或任意命令。

在创建 Qt WebEngine 前注册本地应用和图片协议，用受控 handler 返回脚本、样式或图片。编辑器 profile 拦截未允许的请求，限制导航和子资源，禁用外部子页面、远程资源与未需要的下载权限。Markdown 原始 HTML 采用白名单渲染，并阻止可执行内容、事件属性和脚本链接。受支持的 HTTP/HTTPS 外链只在用户点击时交给系统默认浏览器。悬浮与预览不会访问网页。以受控 QWebChannel 加内容安全策略隔离笔记内容和应用脚本。参考 [Qt WebEngine 自定义协议](https://doc.qt.io/qtforpython-6/PySide6/QtWebEngineCore/QWebEngineUrlScheme.html) 和 [Vditor API 与模式](https://github.com/Vanessa219/vditor)。

### 5.3 保存、历史与崩溃恢复

| 事件 | 状态变化 |
| --- | --- |
| 用户编辑 | 记录单调递增的编辑序号，标记 Dirty，重置 10 秒正式保存防抖。脏状态每约 3 秒尝试持久化草稿。 |
| 防抖到期 | 刷新前端缓冲，后台事务提交该序号。界面标记 Saving。 |
| 切换离开脏标签 | 正式自动保存开启时优先刷新原页缓冲并立即入原库写队列，替代该序号的剩余防抖等待，并按自动保存规则提交。缓冲确认后即可切页，磁盘提交在后台。关闭正式自动保存时刷新并优先持久草稿，正文继续等 Ctrl+S 或用户选择保存。 |
| Ctrl+S | 立即刷新并保存，内容与最后快照有差异时创建手动版本。 |
| 提交成功 | 确认 revision 与 edit_seq。只有当前缓冲等于已确认序号才标 Saved，否则维持 Dirty。清理不晚于已保存序号且来源相同的草稿，后来输入继续保存。 |
| 提交失败 | 维持可见的保存失败状态和内存缓冲，保留当前草稿，允许重试。迁移和恢复中止。关闭前须重试成功或明确放弃。 |
| 关闭脏标签/退出 | 先收集当前内容，提供保存、放弃或取消。保存全部成功才关闭；明确放弃时清理其草稿。多文档关闭支持逐项结果。 |
| 异常退出后打开 | 列出草稿，提供预览、恢复和放弃。若 `base_revision` 已过期，展示当前正文和草稿，允许保留为新文档或显式应用；草稿先保留直至操作验证成功。 |

每文档在写队列中最多一个正在提交的保存。新的普通保存可合并至最新序号，手动保存/关闭/恢复属于明确屏障，必须拿到最终确认。前端迟到事件按 generation 或序号过滤；写入草稿采用序号条件更新，避免旧草稿在较新正式保存后重新出现。输入法仍有组合文本时，保存与切换应读取已提交文本或先完成组合，不打断输入。

切页意图由当前编辑器 generation 与最新编辑序号保护。刷新失败时保留原页、未保存标记和可重试状态。切页后后台保存失败时，原标签显示失败状态并保留缓冲或草稿，允许返回重试。相同序号已提交或在途时复用结果，旧确认不清除随后的修改。未确认当前缓冲或仍需保留失败缓冲时，编辑器资源不可释放。

历史版本为单篇正文快照，能按时间列出、预览、恢复和标记重要。自动保存负责写当前正文；有内容变化且至少间隔 30 分钟时可额外创建一个自动历史版本，连续自动保存受该节流控制。Ctrl+S 可主动创建，重复内容不重复生成。恢复历史版本始终先写当前内容保护快照，再在同一事务更新正文、索引与引用。时间清理默认 90 天，重要版本保留。已有脏编辑时先处理缓冲。版本和草稿保留图片引用，使预览、恢复和备份能找回该时期的资源。

历史列表支持选取同一文档的任意两个已保留版本进行只读比较，界面标明两端的时间和版本标识，并显示相同、增加、删除和改动的内容。复用两次 `Version.preview` 取得 Markdown 纯文本，差异按行计算并在后台生成，长文可取消。比较按发起时读取的版本内容呈现，读取时有端点已经清理则刷新列表并提示。用户切换版本或离开时取消过期请求。进入、阅读和退出比较不创建版本、不改变当前正文、草稿、最近修改时间或编辑器选区。恢复仍走独立确认及保护快照流程。

### 5.4 图像与内部链接

- 本地图像从剪贴板、拖拽、文件选择或 Markdown 导入进入。允许 PNG、JPG/JPEG、GIF（动画）、WebP、SVG 和 BMP，按文件签名与实际可读性验证。尽可能保留原格式。SVG 需要安全解析和过滤可执行内容、外部或内联脚本引用以及网络资源，正文展示与导出只使用通过校验的版本。失败给出原因。
- 资产以 SHA-256 去重，路径由系统 UUID 与已验证扩展名生成。图片缺失显示占位和诊断。修复文件须通过该 UUID 对应的哈希校验。
- 正文图片使用 `![说明](shelf-asset://<asset_uuid>)`。链接使用 `[显示文字](shelf://document/<doc_uuid>)`。处理 URI 时严格验证规范 UUID、协议和可选片段，使用数据库映射获取资源。资源 handler 拒绝以任意路径读取本地文件。
- 「插入内部链接」支持按标题搜索并选择文档；源码也可手输 URI。点击目标时在新标签页打开，已开则切换。目标在回收站或不存在时提示失效。标题、分类变化不改 UUID。导入转换与导出重写见第 7 节。
- 从 A 打开或激活 B 时，在窗口的运行状态中为 B 记下本次内部跳转的来源 A。用户关闭当前 B 且关闭成功时，先返回仍打开的 A，并恢复其原阅读或编辑位置。再次从其他文档跳到 B 时以最近一次有效来源为准，自链接不创建返回关系。来源已关闭、已无效或也在本次批量关闭集合时，沿用普通标签页焦点规则。后台页关闭不抢焦点，取消关页保留当前页及返回关系。

**工程实现中的资产生命周期。** 复用资产管理、每库写队列和 `asset_gc`，无需新增业务模块。

1. `Asset.stage` 在同卷的 `assets/.staging/` 写入临时文件，校验哈希、长度与格式，以同库的短时维护屏障串行处理去重、引用登记和发布。复用的文件也要取得作业保留引用。新文件先在暂存目录持久记录发布意图，然后刷写并移动到不可变的最终路径，确认最终文件可读后再返回 URI。库内正常引用经已提交资产记录解析。提交前预览仅允许当前会话凭有效作业保留引用读取，Web 层只持有受控 URI。
2. 正文保存、历史快照、草稿持久化与导入连通组提交，各自在所属的 SQLite 事务更新其内容和图片关系。事务内登记新资产元数据并校验新引用对应的文件已完整发布，既有图片 UUID 按正常路径复用。只有事务提交后，文件才属于相应的持久化文档或草稿。刚插图的草稿可以先于正式正文提交，此时该图片已属于可恢复的持久草稿。
3. 失败回滚时，仍处于打开编辑缓冲区的图片由该会话保留以供重试。用户放弃、导入组失败或取消、以及操作正常收尾时，等本作业进行中的事务结束再释放它的保留引用。由同一文件服务维护共享文件的多个持有者，释放一项不减损其他持有者。无持有者且无持久关系的待提交文件进入清理。启动在取得库独占锁后检查发布意图记录，保留数据库中已有引用的文件，把确认由本应用创建且未提交的遗留文件纳入清理，无法确认归属的文件保持原样并记录诊断。
4. GC 可在后台找候选。移除前在与资源发布、快照同用的短时维护屏障内复核三类持久化关系、作业保留引用及快照保留引用。确认均不存在后，事务记录 `asset_gc` 的 UUID、路径与哈希并移出资产目录表，再幂等删除文件并完成清理记录。实际移除到记录收尾期间，阻止旧 UUID/路径再次登记，并在重试前复核当前引用与路径归属。重启从清理记录恢复中断工作。备份固定快照资产范围见第 8.1 节。

## 6. 搜索设计

### 6.1 全局搜索

独立入口提供搜索框、分类、标签过滤和结果列表。输入停止约 300 ms 后调度，Enter 立即查。查询内含请求序号、文档库会话和取消令牌。输入、分类、标签或排序变更导致请求过期时，控制器撤销旧防抖并立即发出后台取消信号，切库和退出搜索同样处理。读查询按第 9.3 节协作中断，界面仍以请求序号、会话和 epoch 拒收迟到结果。首次打开且保持空白输入时可按独立筛选浏览。非空输入若经过分词未生成可检索项，显示无结果。列表信息和 FTS 命中来自同一 SQLite 读快照。

进入全局搜索时保存来源库会话和书架状态，含范围、筛选、视图、排序与锚点。用户点「清空搜索」或把非空查询删至空白时，取消该搜索页的请求，清去搜索页条件并恢复此前书架。失效的锚点按第 4.4 节回退。首次打开空搜索页后选分类或标签属于无关键词过滤，仍在搜索页内。打开任一有效结果时按文档 UUID 打开或激活编辑标签页，保留该次搜索，用户可通过搜索入口返回结果。目标已进回收站或失效时提示并刷新结果。

**可检索范围与组合语义（用户已确认）**：每篇活跃文档可通过标题、Markdown 正文（包括正文标题、行内代码和围栏代码）、直接分类名及所有祖先分类名、该文档标签名检索。查询拆成关键词项，每项可以命中任一可检索字段；所有查询项同时满足才返回该文档。例：分类路径 `技术笔记 / C++ / 内存` 的笔记，正文只有 `allocator`，搜索 `C++ allocator` 仍命中。分类路径包含完整的祖先链，因而也能搜索路径上的不同分类名称。普通全文搜索只返回活跃文档。

**独立过滤**：按分类 UUID 选定子树，包括其本身和后代。未分类匹配空 FK。标签使用已去重的 UUID；两个或更多标签默认要求文档具有全部关系。查询逻辑为 `关键词 AND 分类范围 AND 每个所选标签`。分类、标签过滤直接查关系表，空文本也支持过滤。失效标签在界面显式移除前，服务可返回失效筛选错误，不能静默扩大结果。

**匹配和排序实现**：

- `title` 保存标题，`body` 保存原 Markdown 的搜索投影，保留技术代码与原文偏移。`category_path` 按祖先至叶子依次拼接组件，`tag_names` 按稳定顺序拼接显示名称。每个分类路径组件和每个标签名都参与匹配。未分类行使用显示名「未分类」，过滤仍基于空 FK。
- C++ FTS5 自定义 tokenizer 共用于索引与查询，版本绑定本地中文词典和规则。普通 Unicode 按词及中文离线分词，技术词保留作用域、下划线和运算符等字形，例如 `std::vector`、`operator<<`、`__emplace_back`、`C++` 和 `allocator_traits`。同位置派生短标识时，保持完整技术词的边界语义。普通词可匹配前缀，完整匹配优先；引号表示完整词/短语。短语保持顺序且位于同一字段中的同一可显示文本段，标签短语不能跨标签，分类短语不能跨分类分隔符。工程上在投影中使用 tokenizer 可识别、查询不可生成的边界 token，界面只显示原有文案和路径分隔符。
- 构造逐项转义、无字段限定的 FTS5 MATCH 表达式，用 AND 连接各项并绑定 SQL 参数；分类和标签条件独立使用绑定参数。不能对每列分别跑完整 AND 再对列求并集。索引返回原文 UTF-8 字节边界。结果用结构化区间由 Qt 显示，摘要及元数据按文本渲染。仅分类/标签匹配时在对应标签或分类路径上高亮，正文给普通摘录；仅标题匹配同理。
- 由源 Markdown 结构标注正文、行内代码和围栏或缩进代码块的原文区间，用 FTS 命中偏移关联具体片段。结果保留字段高亮，正文片段同时标记「正文」「行内代码」或「代码块」。匹配出现在多个来源时显示相应标记，仅元数据命中时该正文摘录维持普通文本。正文来源标记复用正文投影和同一读快照，不改变四列 FTS 表或 MATCH 语义。
- FTS5 的 `bm25()` 原始返回值越小（通常越负），匹配相关度越高。统一采用方式 B，对原始返回值取反，得到基础得分 `bm25_score = -bm25(活动 FTS 表, 6, 1, 2, 2)`。依次沿用 `title=6`、`body=1`、`category_path=2`、`tag_names=2` 的权重及固定语料校准。保持现有的完整词匹配及同段共现增益，`score = bm25_score + 完整词增益 + 同段共现增益`。以最终 `score DESC` 排序，同分按 `modified_at DESC, id ASC`。保留最近修改、创建、标题排序。采用最终排序键分页，游标绑定查询与 epoch，失效后从第一页查询。参考 [SQLite FTS5 BM25](https://sqlite.org/fts5.html#the_bm25_function)。
- 非空查询的结果项显示「相关度」及本次查询的最终得分。UI 本地化格式化显示，精度不足时可用科学记数格式。得分用于同次查询结果，不表示百分比。查询结果采用时间或标题排序时仍附带该得分。无关键词过滤的 `relevance_score` 为 null，界面省略该项。计算排序与分页使用完整精度。

  以下 SQL 以 A 槽为例，用一条绑定记录演示已有增益如何参与最终排序。完整查询仍按现有规则计算各候选的增益并应用分类和标签筛选。B 槽使用相同列序、权重和排序键。

  ~~~sql
  WITH gains(doc_id, exact_word_gain, same_paragraph_gain) AS (
      VALUES (:gain_doc_id, :exact_word_gain, :same_paragraph_gain)
  )
  SELECT d.id,
         -bm25(search_fts_a, 6, 1, 2, 2)
           + COALESCE(g.exact_word_gain, 0)
           + COALESCE(g.same_paragraph_gain, 0) AS score
  FROM search_fts_a
  JOIN documents AS d ON d.id = search_fts_a.rowid
  LEFT JOIN gains AS g ON g.doc_id = d.id
  WHERE search_fts_a MATCH :match_query AND d.deleted_at IS NULL
  ORDER BY score DESC, d.modified_at DESC, d.id ASC;
  ~~~

### 6.2 索引一致性与维护

| 提交的业务变更 | 同一事务应更新的 FTS 行 |
| --- | --- |
| 新建、正文/标题保存、导入覆盖、历史版本恢复 | 重算相应活跃文档的完整四列投影。 |
| 文档移动分类、分类改名或移动 | 文档移动重算该文档的投影。分类改名或移动重算该节点及所有后代下的活跃文档。 |
| 删除分类并提升子分类 | 按第 4.1 节处理归属。原直接归属的活跃文档更新为「未分类」，提升子树中的活跃文档保留分类关系并按新路径重算投影。文档仍保留原 UUID、正文和有效链接。当前无 FTS 行的回收站文档继续不入索引。分类关系、排序配置、活动 FTS、重建变更集与 `content_epoch` 同事务提交，失败则全部回滚。 |
| 标签改名、删除、合并、文档关联增删 | 操作前收集来源和目标关联文档，并并入操作后的影响集；重算全部受影响活跃文档的最终标签投影。批量操作按文档 ID 去重。 |
| 进回收站、从回收站恢复、永久删除 | 软删除移除索引行；恢复按当前分类和标签重算并插入；永久删除确认索引行缺席。被删除文档的标签关系仍按第 4.4 节维护。 |

写队列用同一事务读完整业务状态、更新活动 FTS、更新重建变更集和 `content_epoch`，提交后广播失效。失败或取消回滚后保持旧投影和旧版本。列表相关的变更即使无需重新分词，也在事务更新 epoch。读线程在一个事务取得活动槽与 epoch，执行 MATCH 和分类/标签筛选，再组装结果。工期验收覆盖并行读写时只能看到一致的提交前或提交后状态。

全量重建在后台使用固定的非活动 A/B 槽，每库同时最多一个重建作业。SQLite 连接使用的 tokenizer 注册名按版本固定。按文档 ID 分页读取并在后台准备投影，使用有界批次经写队列提交至影子槽。并行写在同一事务将受影响 ID（含删除项）和最新 epoch 登记到 `search_rebuild_changes`。影子扫描后从当前快照重算这些 ID，按已处理 epoch 有条件删除登记；期间再次改动的项留到下一批。最后在维护屏障内核对变更集为空，验证行数、索引完整性和 epoch，将活动槽与 `search_index_version` 原子切换并递增 epoch。重建未发布之前，兼容的原索引仍可搜索；没有兼容索引时显示构建状态，完成后再恢复搜索。活动槽交换后，旧槽等待读取旧快照的查询释放后回收。发布前取消或中断只丢弃未发布槽。未完成的影子槽及其变更记录是可重建的数据，库恢复或迁移打开时验证当前活动槽并重新开始任何中断的重建。T05、T14 验证首次构建、增量变化、活动槽切换与失败恢复。

### 6.3 文档内查找

**用户已确认的行为。** Ctrl+F 在当前标签页的最新缓冲区查找，包括未保存内容、行内代码及代码块。提供大小写、全词、匹配总数、当前序号、高亮、上一项、下一项与 Esc 退出。IR 与 Markdown 源码模式都支持。V1.0 查找为字面匹配，文档内替换和正则不在 V1.0 范围内。全局搜索独立维护。

| 查找表面 | 搜索和定位范围 |
| --- | --- |
| 两模式共同可见的正文 | 使用同一套文字匹配及词边界规则。每一逻辑命中在两模式中须一致，可投影到不同位置。跨样式片段的命中可映射为多段，计为一次。 |
| Markdown 源码模式 | 含共同正文，另可匹配源码字面内容，包括链接目标、语法标记和围栏语言标记。重合的可见正文命中只计一次。 |
| Vditor IR 模式 | 在可见正文、链接文字以及真实代码内容上查找。隐藏链接目标、语法标记、注入的行号及编辑器控件不计入 IR 结果。可见且可定位的渲染文本按实际显示匹配。 |

例如 `[SQLite 官方文档](https://sqlite.org)` 的「SQLite 官方文档」在两模式都命中。`https://sqlite.org` 作为隐藏链接目标只在源码模式命中。切换到 IR 后重新计算序号和数量，不跳转到链接文字冒充链接目标。若 URL 本身也出现在可见正文，则该可见出现按正常规则命中。清空查询时清除查找状态。

**工程实现。** 编辑器适配层以同一未保存 Markdown 快照生成映射。共同正文采用可回投的文字片段和源区间，可见片段按段落、代码等逻辑边界组织，共用大小写和全词判断。源码额外匹配包含源码独有区间的字面命中。IR 使用经过验证的可见文本与实际 DOM/编辑位置映射，避免用源码偏移直接操作渲染视图。适配层维护 UTF-16 区间及编辑器定位锚点，跳转前核对当前映射。锁定版 Vditor 原生能力不足时，用适配层在受控编辑 DOM 中构造高亮和定位，禁用会误定位的原生选区行为。查找高亮独立于正文 DOM 的持久化，不触发保存、dirty 或撤销栈变化。映射失效时先重建，确实不能定位的项从本模式的可跳转结果中移除并显示说明，不能用近似位置代替。共同正文及代码的定位是验收要求。

**WebChannel 与状态。** Qt 查找面板发送 `find({request_id, doc_uuid, editor_generation, edit_seq, mode, text, match_case, whole_word, action})`，动作包含查询、上一项、下一项、清除。适配层在当前编辑器确认缓冲区后回复 `find_result`，按第 5.2 节携带版本、标识和实际编辑序号，另含 `request_id`、模式、当前序号和总数。适配层只对请求所指的当前缓冲区应用高亮。缓冲区已推进时，Qt 在收到最新编辑状态后重新请求。Qt 丢弃旧请求、旧文档、旧 generation 或旧编辑序号的结果。改字、切换模式或恢复编辑器后用最新缓冲区重新计算，共同命中仍有效时保留定位。模式切换沿用第 5.1 节的原文和未保存状态规则。查找不读取 SQLite 正文。

**待验证技术问题。** 锁定版 Vditor IR 对链接文字、隐藏语法、代码块及多个文本节点的真实定位能力，在 P3.16 开发前的实施方案中以已验收的双模式样机和最小复现验证。说明原生能力边界及适配层方案，记录同一编辑缓冲从两模式得到的命中和跳转结果。未验证时补齐可行性证据再开始该功能编码。P1.1 可以按原入口开始。参考 [Vditor 编辑器 API](https://github.com/Vanessa219/vditor)。

## 7. 导入与导出

### 7.1 分阶段导入

1. 在后台枚举多选文件或文件夹，递归识别 `.md`、`.markdown`、`.txt`，按 Windows 物理文件身份去重且避免目录联接造成循环。来源留在原位置。预览显示数量、错误、统一分类/标签及文件标题。无分类归未分类。
2. 解码 UTF-8（含 BOM）。设计兼容 UTF-16 BOM，并让其他编码按批次在预览中显式选择后重解码。无法解码的文件作为失败项，保留可定位的路径。默认标题为原文件名去扩展名。正文中的 H1 和其他标题原样保留。TXT 内容按 Markdown 载入，目录层级不转换为分类。统一 LF 后计算源正文 SHA-256。
3. **用户已确认可在预览逐篇改标题。** 每行候选文档都有独立、可编辑的标题字段，首次显示该文档的 `default_title`。Qt 预览模型按 `candidate_id` 记录该行的可选 `title_override`，支持分别修改不同文档，沿用新建文档的标题校验。预览重算时，按相同 `source_key` 带回编辑值。执行前提交控件中仍在编辑的值，明确展示每项将保存到库中的标题。纯预览和重算只修改内存中的导入计划，相关 DTO 见第 3.4 节。
4. 按 SHA-256 查现有和同批正文，匹配字节再认定重复。比较存储正文和仍有效的导入指纹，解决内部 URI 改写造成的二次导入不识别问题。用户真正修改正文后清除导入指纹。集中展示源标题、路径、已匹配文档和当前选项，支持逐项或成批「跳过」「新建」「更新现有」。新建采用该行有效的修改标题或默认文件名，使用新 UUID。更新保留目标 UUID、引用身份与其他元数据，默认保留已有标题。该行显式改过且最终选择「更新现有」时才更新目标标题，预览并列显示旧标题和最终标题。按最终动作应用批次标签并按版本保护规则保留旧正文。打开的未保存标签页先处理保存/冲突。文档允许标题相同。
5. 为最终纳入的项确定 UUID，以规范来源路径为键建立链接映射，标题编辑不更改来源路径、映射身份或正文指纹。对明确映射的相对 Markdown 链接生成 `shelf://document/<uuid>`，保留可解析的显式锚。不能转换的原始链接保持原样，按第 7.2 节分类。跳过项只有明确映射旧文档时可作为目标。解析器按 AST 和源码区间从后向前替换，保留代码示例、未识别链接和排版。对实际引用的本地图片按原 Markdown 所在位置解析，复制、去重并重写为 `shelf-asset://`。找不到本地图片时保留 Markdown 中该图片的原始引用（含相对路径及原始转义），在导入报告记录源 Markdown 路径、图片引用位置、原始地址与缺失原因。缺图显示占位，不生成悬空的 `shelf-asset://` URI 或资产关系。外部图片保留引用并用离线占位，超限和不支持格式进报告。预览列出将读取的外部目录图片。
6. `Import.commit` 重验计划、标题、来源指纹/身份、更新目标 revision、分类、标签和资产。在同一连通组事务中写最终标题至 `documents.title`，同步 `title_sort_key`、revision 和四列 FTS 投影。标题修改本身不写入 Markdown 正文、不改 H1，正文只按既定导入规范与链接/图片重写处理。跳过、失败、回滚和未提交的取消组均不修改既有文档。取消前已经成功提交的组保留，报告明示提交范围与可重试项。报表保留第 7.2 节链接统计、重写图片数、缺图警告与原始引用、逐项状态及原因。大导入受阶段四测得的内存和事务预算约束，测试见 T07。

### 7.2 导入链接报告

识别范围以 Markdown AST 为准，识别需要解析的原有内部文档链接（本地文档候选、`shelf://document/…` 及其指向已有目标的变体）。独立分析链接与图片。代码块、行内代码、外部网页和纯文档内锚点排除于内部链接统计。为每个候选按最终结果归一为以下互斥状态。已有合法且目标存在的应用内部 URI 归入原样保留。

| 状态 | 统计与处理 |
| --- | --- |
| `converted` 成功转换 | 目标可唯一解析，写入 UUID 链接。 |
| `unrecognized` 无法识别 | 链接意图属于本地文档，但路径/目标有歧义或映射无法唯一确定，保留原始链接。 |
| `target_missing` 目标文档不存在 | 可解析为支持的目标路径或 UUID，但无可导入/已存在的对应文档，保留原始链接。 |
| `unsupported_format` 不支持格式 | 已明确指向其他文档类型或不支持的内部 URI 形式，保留原始链接。 |
| `already_valid` 有效原样保留 | 应用内部 URI 已有效，无需改写。 |

`link_summary` 汇总每一状态和 `retained_original`。后者等于 `unrecognized + target_missing + unsupported_format + already_valid`，界面明确标明其为合计。`link_issues` 逐条返回源文件路径、行/列、原始目的地址、状态及原因码。中文失败原因和原始链接同时显示，应用日志只记录原因码与汇总；用户在导入结果中查看具体路径和原文地址。预览显示估算，最终报告只统计已提交导入组；跳过、失败或取消的组单列，不能计入转换成功。T07 验证互斥分类、合计、原样保留和失败组处理。

### 7.3 导出标准 Markdown

单篇、所选多篇、指定分类含子分类、整库均调用同一导出服务。选择目标后先预览、再写出。使用一致读快照确定目标文档、最终相对路径、图片与链接映射。所有范围按分类层级生成相对目录，未分类位于 `未分类/`。统一 `assets/` 存放使用到的图片。文件名为清理后的标题加 `.md`。按 Windows 文件名规则过滤非法字符、结尾空格和点、设备保留名；结合扩展名预算截断可显示字符，避免路径超长。按大小写不敏感规则分配目录和最终文件名，同一目录重名顺次加数字，稳定 ID 决定分配顺序。模板示例为 `笔记.md`、`笔记 (2).md`。分类名 `assets` 等如果与保留输出目录冲突也使用确定性改名。

写出 Markdown 前用 AST 替换导出范围内的内部链接和资源 URI，采用基于导出文件位置的相对路径和正确的 URL 编码。范围外或已删除目标显示可读原链接文字，导出报告记录目标身份和缘由。缺失图片保留替代文字和警告。单篇导出可解析自身链接。生成的文件使用 UTF-8，可在普通 Markdown 编辑器阅读，随目录移动仍可读图。Markdown 导出只包含所选正文和实际引用图片。源代码中的示例 URI 留在代码中。

导出使用目标所在卷的暂存目录，完成写入后验证文件数和结果路径，再发布到新的导出目录。若目标已有文件，提示选择新目录、生成唯一子目录或明确的移交行为，首版默认生成唯一子目录。取消或 I/O 失败清理本作业的临时文件，避免留下看起来已完整的结果。

## 8. 备份、恢复与数据库升级

### 8.1 自动和手动快照

备份统一根目录与库目录、安装目录分离，设计默认位置为用户文档目录下的 `MarkdownShelfBackups/`。可在设置中变更；禁止选择当前库目录及其子目录。子目录使用 `<library_uuid>/`，在界面显示库名称。每份 ZIP 包含 `manifest.json`、`library.json`、一致的 `library.db` 及该数据库快照中的必需 `assets/`。SQLite 快照保留文档与 Markdown 正文、分类、标签、历史版本、持久草稿、库配置和身份数据。清单含库 UUID、格式与 schema 版本、UTC 时间、原因、路径、字节数、逐项 SHA-256 和总数，明确标记自动、手动或升级保护。SHA-256 用于完整性核对，有意外缺失、外部修改、失败或无可用空间时停止发布。

- 应用按用户在「保存与备份」设置的本地时间每日扫描所有已登记库，默认 02:00。使用全局配置键 `backup_local_time` 持久化 `HH:mm`（00:00–23:59），缺省或非法值回退到 02:00，非法值记录诊断。运行中保存设置后重新调度，其他实例按第 3.2 节共享配置。应用关闭期间的最近一次到期任务在下次启动补执行，按当前本地时区计算。夏令时跳过设置分钟时在紧随间隔后的首个有效时刻执行，重复时刻按本地日期去重。
- 实现以「库 UUID、计划所属本地日期」为自动备份去重键，使用现有跨实例任务协调和成功记录。变更执行时间时重新计算最近一次到期时刻，撤销旧时间下尚未开始的自动调度，已运行的作业仍用启动时捕获的日期和目的路径。自动包清单一并记录该计划日期，用于发布后进程中断时重建成功记录。每库只补最近一次已到期且晚于最近成功计划日期的任务。已有在途任务时先等结果，再按最新配置和成功记录重算。失败可重试，仅成功占用计划日期。已开的库由拥有者执行，空闲库由取得同一独占锁的调度任务执行。一个库缺失、被其他未协调实例占用或权限不足时记录原因，其余库继续。超过一次调度周期的失败在恢复可用后重试。调度仅在应用运行时生效。
- 手动备份可选择当前或已登记库。在满足独占和一致性条件后立即执行，显示进度和最终路径。手动、迁移保护和原位保留目录独立于「15 份自动」配额。应有打开目录、校验和可控清理入口。
- 按 `backup-<UTC时间>-<原因>-<作业短ID>.zip` 命名，先写同目录临时文件。重开 ZIP 校验文件清单、哈希、SQLite `integrity_check` 与外键、库 ID 和资源映射，再原子发布。发布后记录结果。以已验证且正式发布的自动包作为唯一清理候选，按快照时间排序仅保留最近 15 份。磁盘满、冲突或中断保留已有有效快照。只清理归属明确的本应用临时文件与合格超额快照。
- 恢复或迁移时重新校验 ZIP 内容。拒绝绝对路径、路径穿越、链接、重名或 Windows 大小写别名、超限展开及资源缺项。分阶段配置单文件、文件数及总展开上限，流式解包逐项核对清单，所有路径必须在暂存根内。以实际流量校验空间与上限，不能仅信任 ZIP 元数据。

**用户已确认的完整资源范围。** 备份点已提交的全部当前文档（包括尚未永久删除的回收站文档）、所有保留的历史版本（含重要版本）和所有已经持久化且可恢复的草稿所引用的图片均为必需资源。同一图片被多处引用时归档一次。仅在编辑器内存或未提交导入组中出现的图片，以及暂存、待发布和未引用文件不进入归档。若草稿先于正文提交，则按持久草稿的引用纳入。资源范围由快照中的事务状态确定。

**工程实现中的快照与校验。**

1. 库拥有者在后台于两个写事务之间取得第 5.4 节的短时维护屏障，完成 SQLite Online Backup 到临时库，按快照数据库中 `document_assets`、`version_assets`、`draft_assets` 的并集登记快照保留引用。冻结事务提交与资产移除直至所有保留引用登记完成，之后解除屏障。记录每个 UUID 的受控路径、预期字节数与 SHA-256，供后续复制使用。允许等价的稳定读快照方案，但读视图和资产保留引用仍须在同一边界内确立。WAL 活跃时使用 SQLite 备份接口。参考 [SQLite Online Backup API](https://sqlite.org/backup.html)。
2. 解除屏障后后台读取临时数据库，按所有者解析可持久化的 `shelf-asset://` 图片引用并对比三类关系和资产目录表。任何缺失 UUID、关系不一致、文件缺失或内容与预期哈希不符均终止。代码示例与外部资源地址不算受管图片。引用关系验证通过后，在临时数据库中删除无持久引用的资产目录项与旧 GC 记录，使归档的资产目录与实际资源一一对应。源库及其当前清理队列保持原样。临时副本收尾后只归档完整 SQLite 主文件。
3. 复制和压缩期间由快照保留引用保护必需文件。写入临时 ZIP，重开验证 SQLite 完整性、外键和库身份。基于 ZIP 中解出的数据库重新导出资源清单，对照清单路径、大小和哈希逐个校验归档文件。必需资产集、归档数据库的资产目录项、实际资产条目及清单中的资产条目必须一致。缺图、错图、I/O 错误或取消均不发布有效包，也不记自动备份成功或触发旧包轮转。成功发布或失败清理后释放快照保留引用。进程崩溃留下的临时 ZIP 没有成功状态，清理后从新快照重试。已正式发布的包按原校验规则识别成功。

### 8.2 同库恢复的发布协议

备份校验通过之后才进入数据替换。原库为 `worklib`，替换成功后恢复内容位于 `worklib`，旧库名为 `worklib_bak`。若该路径存在，使用 `worklib_bak_YYYYMMDD_HHMMSS` 并按需加唯一数字后缀。两者保留同一库 UUID 和文档、分类、标签 UUID；保护目录不登记、不会自动删除。

| 步骤 | 落地条件与失败行为 |
| --- | --- |
| 1. 预检查 | 持久化恢复作业 ID，验证 ZIP、库 UUID、schema、目标权限和可用空间。ZIP 源与发布目标分离。不同 UUID 的 ZIP 走「恢复到空目标」路径。 |
| 2. 冻结并保存 | 禁止新编辑，向每个 Web 编辑器请求最新正文并等待 ACK，提交未完成保存和草稿。任何页无法刷新或保存失败则结束替换并恢复编辑能力。 |
| 3. 安全准备 | 持有库独占和稳定路径锁，阻止后台写入，落地并按第 8.1 节验证安全快照。核验当前库可重新打开。先在同卷相邻暂存目录完整解包，复核 DB、引用表、资产目录及实际文件。必要时迁移暂存库，迁移后重查资源引用，再生成回滚记录。 |
| 4. 关闭旧库 | 停止索引和后台任务，等待资产和快照作业退出并释放引用与文件句柄。处理 WAL 检查点并关闭全部 DB 连接。Windows 重命名遇共享冲突则有限重试，仍失败时留在原路径。 |
| 5. 交换目录 | 先原子重命名原库至保留目录，再把已验证的暂存目录重命名至原位。持久化父目录下的本次作业状态、目标和旧库路径。两次重命名间有可恢复窗口。 |
| 6. 验证并重开 | 在启用写入和刷新界面前，以预期 UUID 重开原路径，复核数据库及三类图片引用与文件的路径、大小和哈希。失败先隔离已发布目录，再还原旧库。成功后持久登记旧库副本，再移除作业日志，显示保留目录、快照时间和结果。登记失败时保留旧目录和可重放的作业日志，重试登记并显示状态。 |

作业日志拟用 `Prepared → OldMoved → NewPublished → Reopened`，每个动作有持久化意图和完成态。重启检查路径和清单，区分日志写入前后的中断：旧目录已移动且新库未发布时优先还原旧库；原位新库已发布时校验并完成或回滚。出现身份不一致、文件被外部占用或已有目标时停止自动重命名、保留所有候选并提示诊断路径。不得覆盖唯一可用副本。自动化故障注入覆盖每个重命名、提交和重开边界。

**旧库副本的手动管理。** 文档库管理页提供「恢复前副本」入口，列出与活动库 UUID 和规范原路径关联的保护副本，显示目录、恢复操作时间和可用性。恢复重开后将作业 ID、目录路径与物理身份写入独立于被交换库目录的受管记录，复用恢复作业日志做幂等登记。相邻的同名目录仅凭名字不可被认可为保护副本。副本搬离或身份不符时标为不可用，界面不提供直接删除。

从列表选择一份副本并点击删除后，第一次确认显示目录、日期及永久删除提示，第二次确认明确执行永久删除。取消任一步都保持目录和记录。确认后用后台任务按 `library_uuid` 与 `copy_id` 删除。核心复用稳定路径锁与独占所有者协调，删除期间与同库恢复和迁移互斥。开始清理前核对目录身份、期望父目录与库元数据，拒绝活动库、其他已登记路径、正在使用的暂存目录及路径重解析。递归清理仅限已验证的副本目录，不跟随重解析点。开始删除前持久化该次作业及已核验的目录身份。成功后更新列表，失败保留记录并显示未开始或部分清理后的待重试状态。部分清理后以受管记录中已核验的物理身份复核同一目录，避免依赖可能已删去的元数据。部分失败的条目不再作为完整副本展示。只有重新经用户确认才重试删除。自动备份轮转、正常升级和后台资源清理均不删除这些副本。

恢复到空目标主要服务新机器迁移。解包使用同样的数据库与资源交叉校验、暂存、迁移、发布和登记。只有 UUID 未被活跃库占用时才登记，若旧登记路径已失效则在成功后重定位该条目。同一 ID 不作为两个同时可写的库注册。迁移到新机后应检查版本、图片、内部链接和工作区，并可重新选择备份根目录。

### 8.3 自动升级

1. 打开时核对身份、格式和 `user_version`。旧版本在取得独占锁后由应用自动迁移。新版库由旧应用拒绝写入，提示需要相应版本。
2. 迁移前生产可验证的整库保护快照。创建暂存库并依版本顺序应用 `migrations/0001_initial.sql`、后续迁移及 C++ 数据转换，执行外键、文档/资源数量、哈希/模式和索引验证。每步在事务中提交，最后同步清单需要的格式标记。
3. 迁移成功后用受保护的目录发布协议切换并重开，旧副本在发布成功前保留。失败则仍可从旧库或保护包恢复，日志和 UI 说明失败的版本、操作 ID、保护包位置。
4. 测试从每个受支持旧 schema 升级、升级后重复启动、未来 schema 拒绝、数据异常、空间不足与中断恢复。应用安装升级与数据 schema 升级是两个可独立失败和恢复的流程。

### 9.2 性能目标与可重复基准

**用户已确认目标**：单个库按 10,000 篇设计。普通全文搜索目标在 1 秒以内，常规文档尽量 1 秒内进入可编辑状态。1 MB 以内保持较好的编辑流畅度。10 MB 级别必须有加载提示及必要保护。导入、索引、备份和搜索不得长期阻塞 UI 主线程。

**测试环境**：目标 Windows x64 上使用 Release 构建、实装 PySide6/Qt WebEngine。参考机为 SSD、16 GiB RAM，记录 Windows 版本、CPU 型号及核心数、磁盘及可用空间、内存、应用和依赖版本。打包版本与源码运行分别记录。冷启动、首次 WebEngine 加载和热路径分别测量。基准使用同一固定种子、同一磁盘位置与配置，记录防病毒软件和其他显著负载。

**测试数据**：固定种子产生 10,000 篇中英文技术笔记，中位约 4 KiB、p95 约 32 KiB，混合长短文档、深分类、多标签、代码和重复词，附共享及独立图片。生成器输出文件数、正文/图片总字节、分类和标签个数、链接数、期望搜索结果与校验值。另设约 1 MB 与约 10 MB 的长文样本各一纯文本、一混合代码/表格/图片引用，记录实际 UTF-8 字节数。预计导入项、可索引行数和备份资源数在试验前固定。对全量测试另用没有活动索引的同数据副本测首次构建。

### 9.3 后台任务、取消与资源验收

- 导入、索引、搜索和备份的文件 I/O、压缩、SQLite、中文分词、Markdown 解析由后台执行。Qt 主线程处理交互、轻量校验和合并后的进度事件，避免大文档跨桥时重复序列化或长时间处理整页渲染。通过有界队列和批次控制峰值。取消/关闭后忽略迟到信号并释放资源。界面显示准备、运行、取消中、完成或失败，提供任务范围和进度。
- 分别在首次导入、全量重建、全库备份和连续搜索期间，按固定脚本执行悬停、按钮点击、滚动或编辑。使用 Qt 主线程计时器心跳并记录真实输入→反馈延迟，采集 p95、最长停顿及掉帧。在健康参考机上的初始预算为输入响应 p95 ≤ 100 ms，持续事件循环停顿不超过 500 ms。记录写事务导致的提交排队，UI 呈现等待状态。
- 取消先停止接受新子任务。读查询使用可中断的后台连接；索引仅在安全批次边界中止。导入保留已提交连通组并报告已写入数量，回滚进行中连通组或等其当前提交点完成，停止后续组。备份在发布前中止并清理暂存，已发布并验证的 ZIP 保留。在短暂不可取消的事务提交或发布边界，显示「正在安全收尾」；最终结果明确提交和未提交的部分。自动化覆盖执行前、长操作中、发布临界点及窗口关闭。
- 取消计时从按钮按下至显示「取消中」，以及至后台停止且完成清理的两个时点。初始工程预算为界面确认 p95 ≤ 100 ms，安全取消完成 p95 ≤ 2 s。不可中断边界单独记录耗时和状态，不能因超预算跳过数据校验。
- 使用 Windows 采样统计应用进程树的 Private Bytes，含 Python 主进程和 Qt WebEngine 子进程；后台 C++ 用同一进程的增量和任务标注归因。记录空闲基线、峰值、退出任务后的采样和磁盘暂存峰值。每任务初始工程预算为相对空闲增量 ≤ 512 MiB、应用进程树峰值 ≤ 1.5 GiB。测试失败的配置可调整处理批量或实现，复跑并记录。内存预算不作为可导入文档的隐式拒绝阈值。

## 10. 逐功能开发路线与导师交付

### 10.1 开发模式 B（强制）

Codex 在每个功能内同时承担软件工程师和技术导师职责。第 10.2–10.6 节中的每一行是独立实施和验收的最小工作单元。阶段用于组织依赖与汇总，功能之间逐项推进。

1. **提出当前功能的实施方案并等待确认。** 给出功能 ID、目标和范围、前置依赖、受影响路径及接口、数据与线程边界、设计取舍、验收用例和计划运行的命令。可以先只读查看项目及前置功能。产品需求按本报告执行，确认针对该功能的实施方案。
2. **收到用户对该方案的确认后才开始代码修改。** 本轮只写该功能及其必要测试和文档。实施时发现需要改变已确认方案或扩大边界，更新该功能方案并等待确认。
3. **完成源码、测试与代码审查。** 检查正确性、边界、资源与线程、失败/取消、旧数据兼容性和回归。运行计划测试及受影响回归，修复问题并复测。保留测试命令、环境、通过/失败/跳过数和实际结果；未运行项及原因明确记录。
4. **交付 Deep 讲解及学习文档。** 在对话中讲解，并同步创建或更新 `docs/development/<功能ID>_<feature>.md`。包含新增和修改的文件、关键类/函数及职责，说明重要参数的类型、含义、取值、生命周期、返回值和错误。按实际入口串讲正常、失败和取消调用链，给出少量关键代码或具体源码定位、可调试入口及复现步骤。复杂功能解释技术原理、为何选当前方案、可行替代、取舍、常见故障和证明正确性的测试。讲解以关键路径、边界和决策为单位。
5. **等待用户对当前功能验收结果的确认。** 提交源码/学习文档路径、实际测试命令及结果、审查发现和未决事项。未确认时停在当前功能，按反馈继续修订、测试与讲解。当前功能验收确认后才进入下一功能的实施方案，随后取得该功能自身的开发前确认。

## 11. Windows 发布方案 C

### 11.1 同一构建，两种发行物

1. 在锁定的 Windows x64 发布环境，构建 C++ Release，安装 `.pyd` 到明确的暂存目录，使用锁定环境跑发布前测试。将版本元数据同步到应用、PyInstaller、Inno Setup 和发布说明。
2. 运行 `pyinstaller --noconfirm --clean packaging/windows/MarkdownShelf.spec`。本设计采用 PyInstaller **onedir** 作为公共载荷。显式归档 Python、Qt、Qt WebEngine 子进程及其资源和 locales、VC 所需运行库、应用 `.pyd`、Vditor 静态文件、语法高亮和中文词典、图标及第三方许可。固定 spec 的资源路径和 hook。验证组件从载荷中定位，无空目录、开发路径或网络依赖。参考 [PyInstaller 打包模式](https://pyinstaller.org/en/stable/operating-mode.html)。
3. 标准安装版用 Inno Setup 编译 `MarkdownShelf.iss`，载荷来自同一 `dist/MarkdownShelf/`。保留稳定 AppId，安装向导可选位置，创建开始菜单快捷方式，支持桌面快捷方式和 Windows 设置卸载。安装和升级写应用目录，用户库保留在其自选路径；运行中先要求关闭正在使用应用目录的实例，不强制结束有未保存编辑的进程。卸载清理程序及快捷方式，保留文档库、备份及用户配置。参考 [Inno Setup 文档](https://jrsoftware.org/inno-setup/documentation/)。
4. 绿色便携版直接压缩同一载荷，附便携启动标识和简体中文运行说明。用户解压后运行 `MarkdownShelf.exe`，无需系统级安装。拟定使用旁置 `portable.flag` 激活邻近的 `profile/` 持久化配置、日志与登记。库路径依然由用户选择，便携根内登记优先保存相对路径以便带走，根外按绝对路径记录，盘符变化可通过打开库重新定位。只读目录启动时明确提示选择可写位置或移动解压目录。升级便携版用新发行目录，迁移便携 profile 与库数据，保留旧目录直至验证。
5. 输出 `MarkdownShelf_Setup_<version>_x64.exe`、`MarkdownShelf_Portable_<version>_x64.zip`、两份 SHA-256、版本说明和可追溯依赖清单。CI 比对共享载荷的版本及关键二进制哈希。应用更新由用户下载安装包或替换便携载荷；V1.0 不集成联网更新。代码签名和外部分发渠道按实际发布环境记录，方案 C 的定义已明确为两种发行形态及对应工具。

## 12. Frontend Design System

**用户已确认的体验**：现代简约、手动切换浅深主题、书架默认网格且可切换列表、左右两栏独立显隐、预留整体 UI 美化升级空间。颜色、字体、组件实现和目录属于工程设计。

### 12.1 四层分工

| 层 | 内容与职责 | 依赖约束 |
| --- | --- | --- |
| Design Tokens | 颜色（背景、表面、正文、弱文字、强调、错误、成功）、字体族/字重/字号/行高、间距、圆角、边框、阴影、图标尺寸、交互状态（hover、pressed、focus、disabled、selected）、动画时长/缓动。输出一组语义名及浅深映射。 | 统一源，集中校验完整性。两种主题共用命名，允许各端字体回退。 |
| 基础组件 | 按钮、输入框、标签 Chip、弹窗、菜单、工具栏、导航栏。管理视觉、键盘焦点、交互状态、可访问名称。 | 消费 Tokens 和主题适配，接收文本/状态并发出通用信号。 |
| 业务组件 | 文档卡片、分类树、标签选择器、搜索结果、编辑器标签页、文档大纲。 | 消费基础组件、DTO 和界面模型，发出带 UUID 或命令 ID 的意图。卡片与文档属性的可点击标签复用第 4.4 节的 UUID 信号及事件隔离。必要样式以语义 token 或组件状态表达。 |
| 页面布局 | 书架首页、编辑器、全局搜索、标签管理、设置、导入、导出、备份、恢复。 | 负责组合和布局，控制器处理信号并经后台任务或 C++ 服务读写业务数据。 |

依赖方向为「页面 → 业务组件 → 基础组件 → 主题契约」。共享 DTO 与命令契约由应用层定义。UI 代码不直接连接 SQLite、写库文件、调用 FTS、执行数据迁移或实现分类/标签业务规则。控制器可替换视图而保持服务接口不变。替换卡片、分类树、编辑器外观或导航布局时，无需修改 C++ 核心和 SQLite 数据模型。

### 12.2 ThemeManager 与跨端适配

- 每进程由统一 `ThemeManager` 读取全局主题配置、校验 token 集、生成不可变主题快照，并发布版本化的 `theme_changed` 信号。切换通过全局设置协调，其他运行中的库窗口在读取全局配置通知后应用同一主题。主题状态与文档修改状态独立。
- `QtThemeAdapter` 将语义 token 映射到 QPalette、集中维护的 QSS、控件状态及图标资源。`WebThemeAdapter` 把同一快照转换为 `{schema_version, theme_id, generation, tokens}`，通过 WebChannel 的 `set_theme` 下发。JS 映射为 CSS 自定义属性，并同步 Vditor 明暗模式、代码高亮和选区。Web 端确认最新 generation，忽略过期事件。
- 页面在 `ready` 后应用最新快照。切换主题保护正文、光标、滚动、撤销、草稿和 dirty 状态。套用失败时使用完整本地默认主题并记诊断错误。业务组件只引用统一 tokens，直接硬编码颜色、间距、阴影和字体的样式应在审查中迁回共享源。阅读器主题和资源保持本地。
- 验收见 T16。用同一 fixture 验证两主题的卡片、弹窗、图标、选区、焦点、禁用状态、键盘导航、左/右栏独立显隐、Web 内容及代码高亮。通过替换一套组件样式和恢复设置进行结构检查，业务模块与 schema 无需改动。
