## 执行命令

开发终端先用 `vcvarsall.bat x64 -vcvars_ver=14.44` 加载工具集。依赖和构建全部指向本地缓存。以下为实际矩阵对应的命令，`$name` 为 `debug` 或 `release`。

```powershell
build/deps/python312/tools/python.exe -m venv .venv
.venv/Scripts/python.exe -m pip install --no-index --find-links build/deps/wheels --require-hashes --only-binary=:all: -r requirements-dev.lock
.venv/Scripts/python.exe -m pip check

$python = (Resolve-Path .venv/Scripts/python.exe).Path
$archives = (Resolve-Path build/deps/archives).Path
$preset = "win-x64-$name"
$build = "build/$preset"
$stage = ".stage/$name"

cmake --fresh --preset $preset -B $build "-DPython_EXECUTABLE=$python" "-DMARKDOWNSHELF_DEPS_DIR=$archives" -DMARKDOWNSHELF_STRICT=ON
cmake --build $build
ctest --test-dir $build --no-tests=error --output-on-failure --output-junit "$PWD/$build/ctest.xml"
cmake --install $build --prefix $stage
$stagePath = (Resolve-Path $stage).Path
$env:PYTHONPATH = "$stagePath;$PWD\src\python"
& $python -c "from pathlib import Path; import sys, sysconfig, _markdownshelf_core as m; p = Path(m.__file__).resolve(); assert p.suffix == '.pyd' and p.parent == Path(sys.argv[1]).resolve(); print(sys.version, sysconfig.get_config_var('EXT_SUFFIX'), p, sep='\n')" $stagePath
& $python -m pytest tests/python "--junitxml=$build/pytest.xml"
dumpbin /headers "$stage/_markdownshelf_core.cp312-win_amd64.pyd"
dumpbin /dependents "$stage/_markdownshelf_core.cp312-win_amd64.pyd"
```

缓存复验将构建目录换成 `build/win-x64-offline-debug` 和 `build/win-x64-offline-release`，暂存目录换成 `.stage/offline-debug` 和 `.stage/offline-release`。两个常规构建目录另直接执行了 `cmake --build --preset` 和 `ctest --preset`，确认预设入口有效。核心独立性和格式检查使用以下命令。

```powershell
cmake --fresh --preset win-x64-debug -B build/win-x64-core-only "-DMARKDOWNSHELF_DEPS_DIR=$archives" -DMARKDOWNSHELF_STRICT=ON -DMARKDOWNSHELF_BUILD_BINDINGS=OFF -DCMAKE_DISABLE_FIND_PACKAGE_Python=ON
cmake --build build/win-x64-core-only
ctest --test-dir build/win-x64-core-only --no-tests=error --output-on-failure --output-junit "$PWD/build/p11-core-only.xml"
$files = (Get-ChildItem src/core,src/bindings,tests/cpp -Recurse -File -Include *.h,*.cpp).FullName
.venv/Scripts/clang-format.exe --dry-run --Werror @files
```

## ABI 与失败验证

两种扩展的 PE 机器类型均为 `8664`（x64）。Debug 和 Release 都导入 `python312.dll`，Debug 使用 `MSVCP140D.dll`、`VCRUNTIME140D.dll`、`VCRUNTIME140_1D.dll` 和 `ucrtbased.dll`，Release 使用相应的发布版 CRT。官方 CPython 3.12.10 x64 实测可加载 Debug，回退条件未触发。

| 暂存前缀 | `_markdownshelf_core.cp312-win_amd64.pyd` SHA-256 |
| --- | --- |
| `.stage/debug` | `DC70E49EDBE922E53CDF139381EA410A775483983E33B4070D6243C39902C1B3` |
| `.stage/release` | `F1466B4934E5A7A894B67A1DAF45D1580F2EFBF3252638E0711D43990D6AFED1` |
| `.stage/offline-debug` | `B54B8972861D1E98A037D364153B512A3176688E445D13A31D7E6D668A0F3A98` |
| `.stage/offline-release` | `A722EB503C734901DA3753C71B807782D50B81B5B8CAFEA97DF7471C8E5B9B75` |

本机原始 CTest 和 pytest 的 JUnit 文件保存在各构建目录内。补齐 clangd 后的构建和 ABI 输出位于 `build/p11-clangd-*.log`。预期失败日志位于 `build/p11-wrong-python.log` 和 `build/p11-bad-cache.log`。

- **解释器不匹配**。用 `cmake --preset win-x64-release -B build/p11-wrong-python -DPython_EXECUTABLE=E:/Python/python.exe` 指向本机 CPython 3.13.5，配置退出 1，报告版本不满足 `3.12...<3.13`。正确解释器重新配置并通过矩阵。
- **缓存归档损坏**。在隔离缓存目录写入伪 `googletest-1.16.0.tar.gz`，用 `cmake --preset win-x64-release -B build/p11-bad-cache -DMARKDOWNSHELF_BUILD_BINDINGS=OFF "-DMARKDOWNSHELF_DEPS_DIR=$badArchives"` 配置，退出 1 并给出 SHA-256 校验错误。正确缓存可在新的输出路径完成构建及测试。
- **首次 Debug 编译探测**。初始 `/Zi` 触发 MSVC C1902。将 Debug 的符号格式设成 `/Z7` 后，从配置、链接到原生导入均复测通过。
- **第三方诊断**。首次严格编译报告 pybind11 的 C28182 和 GoogleTest 的 C6326。对已标记的外部头使用 `/analyze:external-` 后，GoogleTest 宏展开仍在测试源码报 C6326。用一对 `warning(push/pop)` 将该编号的抑制限制于两个测试函数，保留一方其他警告和静态分析。两个配置均已重跑。
