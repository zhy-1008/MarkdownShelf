## 执行命令

构建使用 x64 Developer PowerShell，选用 `vcvarsall.bat x64 -vcvars_ver=14.44`。沿用 P1.1 机器的 SDK 路径修正，测试进程在本地构建目录存放临时文件。[P1.1 环境说明](P1.1_build_and_abi.md#实测环境与依赖)

```powershell
$python = (Resolve-Path .venv/Scripts/python.exe).Path
$archives = (Resolve-Path build/deps/archives).Path
$common = @("-DMARKDOWNSHELF_DEPS_DIR=$archives", "-DMARKDOWNSHELF_STRICT=ON")

# $name 分别为 debug、release。默认构建对应 .stage/debug 与 .stage/release。
$preset = "win-x64-$name"
$build = "build/$preset"
$stage = ".stage/$name"
cmake --fresh --preset $preset -B $build @common "-DPython_EXECUTABLE=$python"
cmake --build $build
ctest --test-dir $build --no-tests=error --output-on-failure --output-junit "$PWD/$build/ctest.xml"
cmake --install $build --prefix $stage
$stagePath = (Resolve-Path $stage).Path
$env:PYTHONPATH = "$stagePath;$PWD\src\python"
& $python -c "from pathlib import Path; import sys, sysconfig, _markdownshelf_core as m; p = Path(m.__file__).resolve(); assert p.suffix == '.pyd' and p.parent == Path(sys.argv[1]).resolve(); print(sys.version, sysconfig.get_config_var('EXT_SUFFIX'), p, sep='\n')" $stagePath
& $python -m pytest tests/python "--junitxml=$build/pytest.xml"
cmake --build --preset $preset
ctest --preset $preset
```

本地归档复验使用相同的配置、构建、CTest、暂存和 pytest 命令，分别把构建目录换成 `build/p12-clean-debug` 和 `build/p12-offline-release`，暂存目录换成 `.stage/p12-clean-debug` 和 `.stage/p12-offline-release`。这两组由新目录配置。本轮还使用 `build/p12-offline-debug` 复测首轮失败修正。

```powershell
cmake --fresh --preset win-x64-debug -B build/win-x64-core-only @common -DMARKDOWNSHELF_BUILD_BINDINGS=OFF -DCMAKE_DISABLE_FIND_PACKAGE_Python=ON
cmake --build build/win-x64-core-only
ctest --test-dir build/win-x64-core-only --no-tests=error --output-on-failure --output-junit "$PWD/build/win-x64-core-only/ctest.xml"
$files = (Get-ChildItem src/core,src/bindings,tests/cpp -Recurse -File -Include *.h,*.cpp).FullName
.venv/Scripts/clang-format.exe --dry-run --Werror @files
& $python -m pip check
dumpbin /linkermember:1 build/p12-offline-release/markdownshelf_core.lib
dumpbin /dependents build/p12-offline-release/markdownshelf_core_tests.exe
```

错误归档验证在单独目录使用内容为 `wrong archive contents` 的同名文件。命令返回 1，CMake 报告 SQLite 归档的 SHA-256 不匹配，日志保存于 `build/p12-bad-cache.log`。

```powershell
cmake --preset win-x64-release -B build/p12-bad-cache "-DMARKDOWNSHELF_DEPS_DIR=$PWD/build/p12-corrupt-archives" -DMARKDOWNSHELF_BUILD_BINDINGS=OFF
```

## 结果与需求证据

| 测试与需求 | 实测结果 |
| --- | --- |
| P1.2-01 / REQ-P1.2-01 | 默认 Debug、默认 Release、缓存 Debug 和缓存 Release 各通过 16 项 CTest、8 项 pytest，并从各自暂存路径导入 x64 扩展。核心独立构建通过 16 项 CTest。所有通过的测试组均为 0 失败、0 跳过。CMake 拒绝错误 SQLite 归档。运行时确认 SQLite 3.54.1 和 FTS5 编译选项。静态库含 `sqlite3_libversion`、`sqlite3_open_v2`，实际使用 SQLite 的测试可执行文件的导入表只有 Windows 与 CRT 依赖。 |
| P1.2-02 / REQ-P1.2-02 | 验证已有文件打开方式、中文及空格文件名、跨重开 UTF-8 与内嵌 NUL、空文本、NULL、64 位整数、外键、WAL、FULL 和有界等待。异常退出后原库可在 Windows 改名、重开并删除。 |
| P1.2-03 / REQ-P1.2-03 | 写提交后新读事务看到数据，持有快照的读事务保持原视图。验证未提交退出、唯一约束异常、SQLite 自动回滚及延迟外键使 COMMIT 失败。另一写连接收到 `SQLITE_BUSY`，原事务释放后可以提交。 |
| P1.2-04 / REQ-P1.2-04 | 验证顺序执行、C++ 数据转换、重开跳过已执行步骤、较新 schema 拒绝、迁移缺项、脚本事务控制拒绝和存量外键违规。第二步故障时 DDL 和数据回滚，重开时 `user_version` 与第一步数据一致，修正后能继续。 |
