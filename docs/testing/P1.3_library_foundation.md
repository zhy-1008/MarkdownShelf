## 执行命令

在 x64 Developer PowerShell 中使用 `vcvarsall.bat x64 -vcvars_ver=14.44`。本机工具链需要指向实际 SDK 路径，配置同 P1.1 的环境说明。[SDK 路径说明](P1.1_build_and_abi.md#实测环境与依赖)

```powershell
$python = (Resolve-Path .venv/Scripts/python.exe).Path
$archives = (Resolve-Path build/deps/archives).Path
$common = @("-DMARKDOWNSHELF_DEPS_DIR=$archives", "-DMARKDOWNSHELF_STRICT=ON")

foreach ($config in @("debug", "release")) {
    $preset = "win-x64-$config"
    $build = "build/$preset"
    $stage = ".stage/p13-$config"
    cmake --preset $preset @common "-DPython_EXECUTABLE=$python"
    cmake --build --preset $preset
    ctest --preset $preset --output-junit "$PWD/$build/ctest.xml"
    cmake --install $build --prefix $stage
    $env:PYTHONPATH = (Resolve-Path $stage).Path
    & $python -c "from pathlib import Path; import sys, _markdownshelf_core as m; p = Path(m.__file__).resolve(); assert p.suffix == '.pyd' and p.parent == Path(sys.argv[1]).resolve()" $env:PYTHONPATH
    & $python -m pytest tests/python -ra -o junit_family=xunit1 "--basetemp=$PWD/$build/p13-pytest-retest" "--junitxml=$build/pytest.xml"
}

cmake --preset win-x64-debug -B build/p13-core-only @common -DMARKDOWNSHELF_BUILD_BINDINGS=OFF -DCMAKE_DISABLE_FIND_PACKAGE_Python=ON
cmake --build build/p13-core-only
ctest --test-dir build/p13-core-only --no-tests=error --output-on-failure --output-junit "$PWD/build/p13-core-only/ctest.xml"
$files = (Get-ChildItem src/core,src/bindings,tests/cpp -Recurse -File -Include *.h,*.cpp).FullName
& .venv/Scripts/clang-format.exe --dry-run --Werror @files
& $python -m pip check
```

默认 Codex 文件系统沙箱拒绝创建目录联接，并使临时目录 DACL 修改未生效。两套 pytest 改在正常 Windows 用户权限下复验，DACL 用例仅改动隔离的 pytest 目录并在结束时撤销拒绝项。Release 另外从 `build/p13-stage-smoke-*` 工作目录用已暂存扩展执行创建、开库和关闭。

日志位于 `build/p13-debug.log`、`build/p13-release.log`、`build/p13-core-only.log`、`build/p13-pytest-debug.log` 和 `build/p13-pytest-release.log`。各构建目录保留 `ctest.xml`，两套绑定另有 `pytest.xml`。耗时原文在对应构建目录的 `Testing/Temporary/LastTest.log`。

## Windows 路径断言复测

提交 `ba2477e` 的托管工作流在 Debug 和 Release 均通过编译，CTest 各有 23 项通过、2 项失败。临时目录使用 `RUNNER~1` 短路径，`Library::create` 返回的规范化路径使用 `runneradmin`。本机将同一临时根的 `build\tmp` 改写为 `BUiLD\tmp`，修正前的 Release 程序复现了路径不等断言和输出 Unicode 路径时的代码页异常。[GitHub Actions #3](https://github.com/zhy-1008/MarkdownShelf/actions/runs/44566319554)

2026-11-25 使用上述 MSVC v143、Windows SDK 和 Python 环境。重新构建三种配置，分别把 `TMP` 和 `TEMP` 指向仓库内的 `build\tmp` 及其 `BUiLD\tmp` 别名，在每种路径写法下运行完整 CTest。两套绑定重新暂存并验证实际导入的 `.pyd` 路径，随后运行完整 pytest。复测对应 REQ-P1.3-01、REQ-P1.3-02、REQ-P1.3-04 和 REQ-P1.3-06。

| 配置 | 正常路径 CTest | 别名路径 CTest | 暂存导入及 pytest |
| --- | --- | --- | --- |
| Debug | 25 通过 | 25 通过 | 导入成功，39 通过 |
| Release | 25 通过 | 25 通过 | 导入成功，39 通过 |
| 独立核心 Debug | 25 通过 | 25 通过 | 无绑定 |

构建命令为 `cmake --build --preset win-x64-debug`、`cmake --build --preset win-x64-release` 和 `cmake --build build/p13-core-only`。CTest 使用对应的 `--preset` 或 `--test-dir build/p13-core-only`，附加 `--no-tests=error --output-on-failure`。绑定用 `cmake --install build/win-x64-<配置> --prefix .stage/p13-ci-fix-<配置>` 暂存，用 `python -m pytest tests/python -ra -o junit_family=xunit1` 运行。最终各组均为 0 失败、0 跳过。沙箱内两组 pytest 各为 37 通过、2 失败，涉及 DACL 与目录联接。切换到普通 Windows 用户权限后，两组均通过。各构建目录有 `p13-ci-fix-*.xml`，格式检查及 `git diff --check` 均通过。

自审核对了 `fs::canonical` 使用测试用例的预期目标计算规范化路径，以及 `u8string()` 输出失败详情时使用 UTF-8。修正后的托管结果等待 GitHub Actions 运行。

## 检查开销与 WAL 观察

`MeasuresMetadataAndQuickCheckOnRepeatableLibraries` 在每个库上预热 1 次后采样 20 次。合成库有 10,000 行，每行 4,096 字节 BLOB。`inspect` 计完整元信息路径，`quick_check(1)` 单独计已打开的只读 SQLite 连接执行快速检查的耗时。结果为微秒，不作为测试阈值。

| Release 样本 | DB 字节量 | inspect p50 / p95 | quick_check p50 / p95 |
| --- | ---: | ---: | ---: |
| 空库 | 8,192 | 750 / 1,044 | 205 / 484 |
| 合成库 | 46,104,576 | 841 / 1,151 | 23,632 / 26,235 |

两套绑定均观察到 SQLite 在检查已关闭的 WAL 库时创建 `library.db-wal` 和 `library.db-shm`。检查前后清单与主库字节相同。目录快照写入 pytest JUnit 属性。合成库结果用于本阶段的开库策略，最终产品性能基准见 V4.0 §9.2。
